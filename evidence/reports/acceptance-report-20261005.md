## 二、V100 的 PCIe 链路问题 —— 已通过换槽解决 ✅

### 问题（换槽前）

```
Tesla V100-SXM2-16GB : PCIe Gen2 ×4    ← 异常
RTX 3060             : PCIe Gen3 ×16   ← 正常
```

表现为 **prefill 只有基线的 22–26%**（这条走 PCIe 传激活），而 decode 只是略低
（权重常驻显存，受影响小）。GPU 本身完全健康 —— SM 时钟 1530 MHz 跑满、P0、无降频。

### 解决（2026-10-05 显卡换槽）

把 V100 与 3060 的插槽对调后：

| | 换槽前 | **换槽后** |
|---|---|---|
| **V100** | Gen2 ×4 ❌ | **Gen3 ×16** ✅ |
| 3060 | Gen3 ×16 | Gen2 ×4 |

两个模型的表现全面改善（详见第八节）。3060 挪到 Gen2×4 后仍有 40.3 tok/s（在 40–50 基线内），
因为它权重全在显存里、对带宽不敏感，影响可接受。

**结论**：原来的槽是 x4 电气规格（或 PCIe 速率被限到 Gen2）。V100 是 SXM2 接口，
经转接板接到主板，**必须插在 CPU 直连的全长 x16 槽**才能跑满。

## 三、NInfer 主路线：模型格式不兼容（DOWNLOADS.md 已预警）

kit 启动报错：

```
ninfer-serve: unknown tensor format: PQ2_0_G128
```

逐格式核对 `model.ninfer` 与 kit 二进制：

| 模型用到的格式 | tensor 数 | kit 是否支持 |
|---|---|---|
| PQ2_0_G128 | 322 | ❌ **不支持** |
| Q4G64_F16S | 55 | ✅ |
| Q5G64_F16S | 54 | ✅ |
| W8G32_F16S | 7 | ✅ |
| Q6G64_F16S | 1 | ✅ |
| BF16 / FP32 / I32 | 681 | ✅ |

`PQ2_0_G128` 是主力权重格式（322 个 tensor）→ **此 kit 无法加载该模型**。

这正是 `DOWNLOADS.md` 第 63–68 行预警的情况：模型来自 `iamwavecut/ninfer-all`，
而 kit 来自 `Don-Chad/ninfer-3090`，同上游两个 fork，格式集合不同。
文档当时给的处置是「直接切降级路线，不要死磕」—— 已照此执行。

另外模型身份也值得记录：`model.ninfer` 头部 `identity.model_id` 实为 **`qwen3.8-27b`**
（`weights_id: groupwise-int`），并非文件名暗示的 Bonsai2。kit 自带
`kit/scripts/ninfer-argv.txt` 引用的也是 `qwen3_8_27b.ninfer`。

### 顺带修掉的 CLI 差异

`start-3060-bonsai2.sh` 原按旧引擎写的参数，此 kit 不认：

| 旧脚本用的 | 此 kit |
|---|---|
| `--host-state-slots 8` | ❌ 无此参数 |
| `--host-kv-mib 2048` | ❌ 无此参数 |
| `--log-level info` | ❌ 无此参数 |
| `--spec dflash2` | ⚠️ 只有 `dflash`（无 `2`）|

已按 `ninfer-argv.txt` 修正。
